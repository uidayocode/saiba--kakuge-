# 『電脳奉納試合（でんのう ほうのう じあい）』 実装設計書 v1.0

対象ファイル: `fighting/game.html`（エンジン担当 Sonnet）/ `fighting/data.js`（データ担当 Haiku）
関連: 同展示の弾幕STG設計書 `design.md`（`data.js` は純粋なデータ、`validateGameData` で検査、の方針を踏襲）

目的: 2人が互いのファイルを見なくても並行作業できるよう、**データ契約（4章）と数値（2章）を先に固定する**。
両者が共有するのは **4章（スキーマ）・8章（サンプル）・9章（バランス）** だけでよい。

## 0. 全体方針と共通ルール

### 0.1 ゴールと優先度
最重視は「ぬるぬる動く」「2人でちゃんと遊べる」。次の3層で実現する。

| 層 | 内容 |
|---|---|
| ロジック | **60Hz固定タイムステップ**。フレーム単位のデータ（発生/持続/硬直）で決定論的に動く |
| 描画 | rAFで毎フレーム描く。**ロジック状態を前回/今回の2点保持し、alphaで補間**（144Hzでも滑らか） |
| 絵 | ボーン人形 + **キーフレーム補間（イージング付き）** + クリップ間ブレンド + 二次揺れ（髪・袖・尻尾） |

実装優先度（エンジン担当向け）:
- **P0**: 固定ステップ、補間描画、リグ描画、アニメ再生、入力（KB+パッド）、戦闘ルール一式、HUD、4キャラ、画面遷移、SE、**`#selftest`（5.10）・`#debug`・`#gallery`（5.11）**（テスト用の仕組みは最初から作る）
- **P1**: 入力設定画面とウィザード、グリッチ演出、おみくじ、二次揺れ、残像/軌跡、キャンセル/コンボ補正
- **P2**: BGM（任意の生成音）、練習モード（ダミー相手）、スミア表現、デバッグ録画
- **スコープ外**: CPU対戦AI、オンライン、リプレイ保存、ラウンドごとのステージ違い（ステージは1種）

### 0.2 座標系と単位（両者共通の契約）

| 空間 | 規約 |
|---|---|
| 論理解像度（画面） | **960 x 540 px**。原点は左上、x右+、y下+。この大きさで描いてCSSで拡大 |
| ワールド | 横 **1280 px**（x: 0〜1280）。地面は画面上 y=460 のライン。x右+ |
| **キャラクター空間（データ契約で使う）** | 原点 = **足元の中心（地面）**。**x = 向いている方向（前）が+**、**y = 地面からの高さが+（上向き）**。左向きのキャラはエンジンが描画/判定時に反転する。データは常に「右向き」で書く |
| 時間 | **フレーム（1/60秒）** が基本。「秒」はUI演出のみ |
| 速度/加速度 | px/フレーム、px/フレーム²（例: 歩き 3.4、重力 0.75） |
| 角度 | 度（deg）。ボーン角の規約は 4.9 章 |
| 判定ボックス | `{x, y, w, h}` = キャラクター空間で **x〜x+w（前方）、y〜y+h（上方）** を覆う矩形。x,yは矩形の「後ろ下の角」 |

### 0.3 色
- **色トークン**（STG設計書と同一）: `pink #ff4fa3` / `cyan #19f3ff` / `yellow #ffe94d` / `green #7cff6b` / `violet #a56bff` / `red #ff3b5c` / `orange #ffa13c` / `white #f4f7ff` / `gold #ffd24a` / `blue #4d7cff`
- データ中で「色」と書いた欄: **トークン名**、ただし `look.palette` / `look.paletteP2` と `stage.colors` だけは `"#rrggbb"`（小文字6桁）。
- `look` 内の `color` 欄は **palette のキー名**（`"primary"` など）で指定する（16進を直書きしない）。

### 0.4 ID・命名
- キャラID・弾ID・クリップ名: `[A-Za-z0-9_]+`。技IDだけは固定の10個（4.12）で、`"5L"` のように数字で始まるため**オブジェクトのキーは必ず引用符**で囲む。
- 参照先が存在しなければ検証エラー（クリップ名、弾ID、キャンセル先の技IDなど）。

### 0.5 data.js のルール
1. **純粋なデータのみ**（関数・外部参照・`eval`・コメント内の指示禁止）。UTF-8。`window.GAME_DATA = {...};` の1文のみ。
2. 数値は小数可（px/フレーム系）。フレーム数は**整数**。
3. 読み込みは `<script src="data.js" charset="utf-8"></script>` を本体 `<script>` より前に置く。
4. エンジンは起動時に `validateGameData(GAME_DATA)` を実行し、`{errors:[], warnings:[]}` を**コンソールとデバッグ画面に全件列挙**。errors があれば画面に「DATA ERROR」を出して起動を止める。warnings は表示のみ。
5. エンジン定数（2章の数値、コマンド文字列、簡易操作のマッピング、SFX名の実体）は**game.html側に持つ**。data.js にはキャラごとの差分だけを書く。

### 0.6 結合手順
1. Sonnet は **8章のサンプルをそのまま仮の data.js**（`roster: ["miko"]` のみ）として開発を始める。エンジンは roster が 1〜4 件でも動くこと（1件なら同キャラ対戦）。
2. Haiku は 8章を雛形に、9章の数値表から残り3キャラを作り、`game.html#debug` で `validateGameData` を通し、`#gallery` で絵の崩れを確認する。最終 roster は4件（`["miko","komainu","oni404","fox"]`）。
3. 見た目（ポーズの良し悪し）は実機で見て調整する前提。**契約に反する値だけは検証で必ず弾く**。

## 1. 画面遷移と各画面の仕様

### 1.1 遷移図

```
BOOT ─(任意の入力: AudioContext起動 + パッド認識)→ TITLE
TITLE ─(対戦開始)→ CHAR_SELECT ─(両者決定)→ VERSUS ─→ FIGHT ─(勝敗)→ RESULT
TITLE ─(入力設定)→ INPUT_CONFIG ─(戻る)→ TITLE
TITLE ─(設定)→ SETTINGS ─(戻る)→ TITLE
TITLE ─(あそびかた)→ HOWTO ─(戻る)→ TITLE
CHAR_SELECT ─(Start長押し or 「入力設定」ボタン)→ INPUT_CONFIG ─→ CHAR_SELECT
CHAR_SELECT ─(両者キャンセル/戻る)→ TITLE
FIGHT ─(Start)→ PAUSE ─(再開 / 入力設定 / キャラ選択へ / タイトルへ)
RESULT ─(もう一度)→ VERSUS（同キャラ・同設定）
RESULT ─(キャラ選択へ)→ CHAR_SELECT
RESULT ─(タイトルへ)→ TITLE
放置タイムアウト（1.4）→ TITLE
```
「入力設定（任意）」はタイトルとキャラ選択のどちらからも入れる。初回起動時、パッドが接続されていればタイトルに「Joy-Conは入力設定でボタンを確認してください」の案内を出す（強制はしない）。

### 1.2 各画面の仕様

**BOOT**: 中央に「ボタンを押してください（Joy-Con / ゲームパッド / キーボード）」を点滅。押下で `AudioContext` を `resume`、パッド一覧を更新、`TITLE` へ。（Gamepad APIは何か押すまでパッドが見えないブラウザがあるための画面）

**TITLE**:
- 背景: ステージ（6.3）をゆっくりカメラパンしたもの。中央に `texts.title`「電脳奉納試合」ロゴ（ネオン、Orbitron + DotGothic16）、下に `titleEn`、`tagline`。
- メニュー（上下で選択、弱=決定、強=戻る）: **対戦開始 / 入力設定 / 設定 / あそびかた**。
- 右上に**接続状況バッジ**（1.5）。下部に `hints` を8秒ごとに切替。
- 30秒操作が無ければキャラ紹介デモ（4キャラが順に `intro`/`win` クリップを再生）に切り替え、何か押すと復帰。

**HOWTO**: `texts.howto`（最大8行）+ 操作図（簡易操作/通常操作の対応表）。

**SETTINGS**（項目は左右で変更、即時保存）: 音量(0〜10) / 画面揺れ(ON/OFF) / グリッチ演出(ON/OFF) / 走査線(ON/OFF) / 本数(1/2/3、既定2) / 制限時間(60/99/無制限、既定99) / 簡易操作の既定(P1/P2それぞれON/OFF、既定ON) / 設定の初期化。

**INPUT_CONFIG**: 3.5章（ボタン設定画面）。

**CHAR_SELECT（2人同時）**:
- 画面中央に4枚のカード（`roster`順 + 末尾に「ランダム」）。P1カーソル=cyan、P2カーソル=pink。**各自のデバイスで独立に**左右移動、弱=決定、強=取消（決定済みなら決定解除、未決定なら戻る）、必殺=「簡易操作」ON/OFF切替。
- 左右にホバー中キャラの**大きなプレビュー**（実際のリグが `idle` を再生、決定時に `intro` の一部）。名前、`title`、`blurb`、`ratings` 4本（攻撃/速度/リーチ/防御、1〜5のバー）、`quotes.select` を吹き出し。
- 同一キャラ選択可。同一キャラ時は **P2が `paletteP2`** を使う（異キャラ時は両者とも `palette`）。
- 下部に各P枠: デバイス名、接続状態、「簡易操作: ON」バッジ。両者決定で1.0秒後に VERSUS。決定後60分の1秒ではなく**フレームで60F**待つ（その間に取消できる）。
- パッドが後から接続/切断されたらトースト通知し、デバイス割り当て（3.2）を再評価。

**VERSUS**: 120F。左右から両キャラが `intro` の1コマ目をポーズでスライドイン、中央に「P1 名前 VS 名前 P2」、ステージ名 `stage.name`。

**FIGHT**: 1.3章。

**RESULT**: 勝者の `win` クリップ + 敗者の `lose` クリップ。
1. 「WIN」の文字 → 勝者の `quotes.win` からランダム1行を吹き出し。
2. **おみくじ風の一言**: 巻物が開くアニメ（90F）→ 運勢（大吉〜大凶、巨大文字）→ `fortunes.ranks[].lines` からランダム1行。運勢は 2.12 の「勝利ポイント」で決まる。
3. 戦績（取得ラウンド、残HP%、最大コンボ、ノーダメージ有無）。
4. メニュー: **もう一度 / キャラ選択へ / タイトルへ**（左右 + 弱）。ドロー（延長戦でも決着せず）の場合は「DRAW」表示で `fortunes` は出さず、メニューのみ。

**PAUSE**: Start（キーボードは Enter / Esc / 各自のStartキー）で開く。メニュー: 再開 / 入力設定 / キャラ選択へ / タイトルへ。開いたデバイス（またはどのデバイスでも）で操作可。ウィンドウ `blur` / `visibilitychange`、パッド切断でも自動ポーズ。

### 1.3 FIGHT のサブ状態（ラウンド進行）

| サブ状態 | フレーム | 内容 | 次 |
|---|---|---|---|
| `ROUND_INTRO` | 90 | 両者開始位置へ。`intro` クリップ再生。バナー「ROUND n」（最終は「FINAL ROUND」）。操作不可 | `READY` |
| `READY` | 40 | バナー「FIGHT!」を出すと同時に操作解禁（バナー表示開始フレームが操作可能な最初のフレーム） | `FIGHTING` |
| `FIGHTING` | 可変 | 通常戦闘。タイマー進行 | KO or 時間切れ |
| `KO` | 60 | 最後の一撃でヒットストップ28F、その後 **timeScale 0.3 のスローモーション**で60ロジックフレーム（実時間約3.3秒）。敗者は「浄化」演出（6.6）。バナー `texts.banners.ko`「浄化完了」 | `ROUND_END` |
| `TIME_UP` | 60 | バナー「TIME UP」→ HP割合の高い方が勝ち。同率はドロー | `ROUND_END` |
| `ROUND_END` | 120 | 勝者が `win`、敗者が `lose`/`down`。勝ちピップ点灯。ノーダメージなら「PERFECT」 | 次ラウンド or `MATCH_END` |
| `MATCH_END` | 30 | フェードして RESULT へ | `RESULT` |

- ラウンド間: HPは全回復、位置は初期位置（P1 x=500 / P2 x=780）、**ゲージは持ち越し**。
- ドロー: 双方に1ラウンド加算。双方が勝利数に達したら**延長戦**（1回のみ。HPは各50%で開始、制限時間99）。延長戦もドローなら試合ドロー。
- 同時KO（HPが同一フレームで0）はドロー扱い。

### 1.4 放置タイムアウト（タイトルへ戻る）

| 画面 | 無操作時間 | 備考 |
|---|---|---|
| CHAR_SELECT | 60秒 | 残り10秒でカウントダウン表示 |
| INPUT_CONFIG / SETTINGS / HOWTO | 90秒 | キャプチャ待機中は延長 |
| RESULT | 45秒 | |
| FIGHT（両者無入力） | 40秒 | 30秒で警告「10秒後にタイトルへ戻ります」。どちらかが入力で解除 |
| TITLE | 30秒でデモ表示（戻る先ではない） | |

「操作」= 2つのスロットのどちらかのデバイスの、ボタン/方向の変化。

### 1.5 接続状況の表示（必須）
- 非戦闘画面の**右上に常時**: `P1 [KB1] ●` `P2 [JOY-CON(R)] ●`（●は接続=緑/切断=赤/未割当=灰）。パッドは短縮名（`Joy-Con (R)` など）を表示。
- 接続/切断で**トースト**（「Joy-Con (L) が接続されました」「P2のコントローラーが切断されました」）。
- FIGHT中の切断: 自動ポーズ + 「P2 コントローラー切断。再接続するか、キーボードのEnterで継続（P2はキーボードに切替）」。再接続（同じプロファイルキー）で自動復帰。
- 入力設定画面では詳細（`gamepad.id`、`index`、`mapping`、軸/ボタン数、生の軸値）をリアルタイム表示。

### 1.6 入力の取りこぼし対策
- 各シーン入場から**24F（0.4秒）は決定入力を無視**（前画面の連打で飛ばさないため）。
- メニューの上下左右は初回押下で即反応、**押しっぱなしで 24F後から 6F間隔のリピート**。
- キーボードの `event.repeat` は無視（状態は `keydown`/`keyup` で管理）。
- `blur` で全入力を解除。

## 2. ゲームシステム数値（エンジン定数 `CONFIG`）

> 以降の数値は**game.html側の定数**。キャラ固有の値（HP、歩き速度、技のフレーム/ダメージなど）はdata.jsに書く。

### 2.1 固定ステップと時間

| 項目 | 値 |
|---|---|
| ロジック周波数 | 60Hz（`STEP = 1/60` 秒） |
| 1回のrAFで回す最大ステップ数 | 5（超えたら捨てて`acc`をリセット。タブ復帰時の暴走防止） |
| `acc` 加算 | `acc += min(realDt, 0.1) * timeScale` |
| 描画補間係数 | `alpha = acc / STEP`（0〜1） |
| timeScale | 通常1.0 / KOスロー0.3 / 超必殺フラッシュ中0（演出タイマーは別） / ポーズ0 |
| ヒットストップ | **フレーム数でロジックを止める**（timeScaleは使わない）。描画は止まらず、被弾側は微振動 |

### 2.2 ステージ・位置・カメラ

| 項目 | 値 |
|---|---|
| ステージ幅 | 1280 px（ワールド x: 0〜1280） |
| 地面 | y=460（画面） |
| 開始位置 | P1 x=500 / P2 x=780（間隔280px。P1が左、右向き） |
| 画面端（壁）の位置制限 | キャラ中心x ∈ [40, 1240] |
| 2人の最大距離 | **880 px**（これ以上離れない。一方が壁際でなくても、離れる側の移動をクランプ） |
| カメラ中心x | 2人の中点。ステージ端でクランプ |
| ズーム | `viewW = clamp(dist + 440, 768, 960)`、`zoom = 960 / viewW`（1.0〜1.25）。ズーム中心は画面座標 (480, 460)（地面が動かない） |
| 追従 | カメラ位置/ズームは**ロジックフレームごとに目標へ減衰追従**（x: 0.18、zoom: 0.10）。補間描画の対象 |
| 縦 | 最高点のキャラの高さが120pxを超えた分の0.35倍だけ下へスクロール（最大40px） |
| 壁際の画面端 | 画面左右端（カメラ視野 ±30px）も移動制限にする |

### 2.3 体力・ゲージ・勝敗

| 項目 | 値 |
|---|---|
| HP | キャラの `stats.hp`（標準 1000） |
| 勝利ラウンド数 | 2本先取（設定で1/2/3） |
| 制限時間 | 99秒（設定で60/99/∞）。**60ロジックフレームで1秒減**（`FIGHTING`中のみ。超必殺フラッシュ中は止まる） |
| 時間切れ | HP割合の高い方の勝ち。同率はドロー |
| ゲージ最大 | 1000 |
| 超必殺コスト | 1000（全消費） |
| ゲージ獲得（攻撃側） | ヒット時 `hit.gauge.hit` / ガード時 `hit.gauge.block`（データ） |
| ゲージ獲得（防御側） | 受けたダメージ x 0.6（ガード時は chip x 0.6）、小数切り捨て |
| 空振り | 加算なし |
| キャラ補正 | `stats.gaugeMul` を獲得量に乗算（攻守とも） |
| 追い込まれ補正 | 自分のHPが25%以下で獲得量 x 1.5 |
| 超必殺中 | 超必殺のヒットではゲージが増えない（攻守とも） |
| ラウンド間 | ゲージ持ち越し。試合開始時 0 |

### 2.4 ダメージ

- 最終ダメージ = `max(1, round(hit.damage x comboScale))`。
- **コンボ補正 `comboScale`**: そのコンボ中に当たった「技の回数」で決まる（多段技は1回と数える）。

| 何回目の技か | 1 | 2 | 3 | 4 | 5 | 6 | 7 | 8以降 |
|---|---|---|---|---|---|---|---|---|
| 係数 | 1.00 | 0.90 | 0.80 | 0.70 | 0.60 | 0.50 | 0.40 | 0.30 |

- 超必殺の最低補正 = **0.40**（`max(comboScale, 0.4)`）。投げ（コマンド投げ含む）は補正を受けるが最低0.5。
- **のけぞり補正**: n回目の技のヒットストンは `hitstun x stunScale[n]`（四捨五入、最低6F）。`stunScale = [1, 1, 0.95, 0.90, 0.85, 0.80, 0.75, 0.70]`（8回目以降0.70）。
- **ガードダメージ（削り）**: `min(hit.chip, 現HP - 1)`（**削りでは倒せない**）。
- 「コンボ」の定義: 被弾側が連続して（ガード/復帰/ダウン起き上がりを挟まず）ヒットされ続けている間。被弾側が行動可能になった時点でリセット。ダウン中・起き上がり無敵中に受けた次の技は新コンボ。

### 2.5 ヒットストップ（フレーム）

| 種別 | 値 |
|---|---|
| 技のヒット/ガード | `hit.hitstop`（弱 6 / 強 10 / 必殺 8〜12 / 超必殺の各段 3〜4、最終段 16〜20）。**攻撃側・防御側とも停止** |
| 飛び道具のヒット/ガード | 被弾側のみ停止（`hit.hitstop`） |
| 投げ成立 | 12F（投げ側・被投げ側とも） |
| KOの最後の一撃 | 28F に延長 |
| 超必殺フラッシュ | 発動時に40F、ロジック全停止（暗転 + カットイン）。入力はバッファに入る |
| 停止中の挙動 | アニメ時間・状態タイマー・バッファの経過（自分の分）は進めない。被弾側は描画のみ ±(1〜3)px で微振動（impactに比例）。パーティクル/カメラ揺れ/エフェクトは進行 |

### 2.6 のけぞり・ガード・ノックバック

- のけぞり（ヒット）: ヒットストップ終了後から `hitstun`（補正後）フレーム。ガード硬直: 同様に `blockstun`。
- **フレーム有利の定義**: ヒットがアクティブ`k`フレーム目(1始まり)で成立したとき、攻撃側の残り = `(active - k) + recovery`。有利フレーム = `hitstun - 残り`（ガード時は `blockstun - 残り`）。目安は9章。
- ノックバック: `hit.knock.hit / block`（px合計）。ヒットストップ終了後の**10フレームで線形減衰**: 第i(0〜9)フレームの移動量 = `D x (10 - i) / 55`。
- **壁際**: 防御側が壁（またはカメラ端）で動けない場合、動けなかった分を**攻撃側が後ろへ押し戻される**（飛び道具の場合は押し戻しなし）。
- ガード方向の判定は 2.9。

### 2.7 空中・ダウン・起き上がり

| 項目 | 値 |
|---|---|
| ジャンプ | 発生前の屈伸 `stats.prejump`（標準4F、無防備）。vyは `stats.jumpVy`、横速度は入力方向で `±stats.jumpVx`（方向はジャンプ開始フレームの入力で固定） |
| 重力 | `stats.gravity`（標準0.75 px/F²、毎フレーム vy -= g） |
| 着地硬直 | 通常ジャンプ `stats.landLag`（標準3F）。空中技の着地は `move.landLag`（省略時 `stats.landLag`） |
| 空中での向き | 空中は向き固定（着地時に再判定） |
| 二段ジャンプ | `stats.airJumps` 回（既定0、狐のみ1）。空中で↑を新規に押す。空中技の後は不可 |
| 空中ヒット（stun効果）| 空中の相手に `effect:"stun"` が当たると**空中やられ**に移行: `vx = 2.5(攻撃側と反対向き)`、`vy = max(vy, 5)`。ジャグル残量を1消費 |
| ジャグル | `launch` で打ち上げた時に被弾側へ `hit.juggle`（既定3）を付与。空中の相手への追撃ヒットごとに-1、0なら当たらない（`juggle:0` の技は追撃不可） |
| 空中やられ | 地面に着くまで行動不可。`hurtAir` クリップ |
| ダウン | 着地後、`DOWN` 状態 **28F**（`down`クリップ）。この間は**完全無敵**（攻撃も投げも当たらない） |
| 受け身（クイックライズ）| 着地から**6F以内**に任意の攻撃ボタンまたは↓を押す → `DOWN` を飛ばして `WAKEUP`（クイック版 14F）へ |
| 起き上がり | `WAKEUP` **18F**（通常）/ 14F（クイック）。**全フレーム無敵（打撃・投げ・飛び道具）**。終了と同時に行動可能。入力はバッファされ、行動可能な最初のフレームに実行（リバーサル可） |
| 即死の投げ | 地上ヒット硬直中/ブロック硬直中/空中/ダウン/起き上がり中の相手は投げられない |
| 倒れた時の向き | 倒れる方向は被弾時の攻撃側と反対 |

### 2.8 移動とダッシュ

| 項目 | 規則 |
|---|---|
| 歩き | `stats.walkF` / `walkB` px/F。方向キーを押している間 |
| しゃがみ | ↓。しゃがみ中は歩けない。しゃがみ姿勢でも後ろ入力でしゃがみガード |
| ダッシュ（前） | →→（ダブルタップ。猶予 **12F**）で `stats.dashF.frames` フレーム。速度は「最初の70%は `speed` 一定、最後の30%で0まで線形減速」。ダッシュ中は攻撃/ジャンプにキャンセル可（開始6F以降）。ガード不可 |
| バックステップ | ←←。`stats.dashB.frames` フレーム。**最初の `invuln` フレームは打撃無敵**。空中不可。着地硬直なし |
| 前進/後退の判定 | 「前」は相手の方向（向き）に対する相対方向 |
| 向き（地上） | 行動可能な状態（待機/歩き/しゃがみ/着地後）で毎フレーム相手の方向に自動で向き直る。攻撃中・やられ中・空中は固定 |

### 2.9 ガード・めくり防止（重要）

**ガード成立条件**（被弾判定の瞬間に評価）
1. 防御側が地上で、状態が `IDLE / WALK / CROUCH / DASH_B（無敵後）/ BLOCKSTUN / LANDING` のいずれか（攻撃モーション中・ダッシュ前進中・ジャンプ中・やられ中は不可）。
2. **後ろ入力**（攻撃側の「位置」に対して後ろ方向）が、判定フレーム、または**直前3F以内(`GUARD_GRACE`)に1F以上**あり、かつ判定フレームに「前入力」ではない。
3. 上下: **↓を押している=しゃがみガード、押していない=立ちガード**。
4. 打点レベル（`hit.level`）との適合:
   - `mid`: 立ち/しゃがみどちらでも防げる
   - `low`: しゃがみガードのみ（立ちガードは食らう）
   - `high`: 立ちガードのみ（しゃがみガードは食らう）

**めくり防止（クロスアップの理不尽防止）**
- 後ろ方向の基準は**向き(facing)ではなく攻撃側の現在位置**（相手側 = 攻撃側のx座標が防御側より小さければ左側）。飛び越えた瞬間から「画面上で相手から遠ざかる方向」を押せばガードできる。
- **めくり猶予**: 飛び越え直後の攻撃で、ヒット時点の両者のx差が **±12 px以内**のときは、飛び越え**前**の位置関係を基準にガード方向を評価する（どちらの方向でもガード可）。
- 飛び越え側は空中で向き固定のため、着地するまでは進行方向と向きが逆になりうる（これは仕様）。
- ジャンプ攻撃の `level` は `mid`（据え置き。択を増やさないため）。上段 `high` は一部地上技のみ。
- 空中ガードは存在しない。

### 2.10 押し合い判定・画面端

- 各キャラは**押し合いボックス（pushbox）**を持つ（`boxes.push`、中心がキャラx、足元が高さ0）。
- 重なったら、**重なり量の半分ずつ**を左右に押し出す（1フレームの補正は各キャラ最大4px）。一方が壁/カメラ端で動けない場合は**もう一方が全量を押し戻される**。
- 空中のキャラの足元の高さが相手の pushbox 高さ以上なら**押し合いを無視**（飛び越え可能）。
- 同じフレームでの位置関係が入れ替わった（めくった）場合: 自動向き直しは着地まで行わない（2.9）。
- 壁際コーナーで押し戻されるときに画面端を超えない。2人が完全に重なった場合（同x）は、直前に左側だった方を左へ。

### 2.11 投げ・投げ抜け

| 項目 | 値 |
|---|---|
| 入力 | **弱+強 の同時押し**（猶予3F）、または専用ボタン `T`（投げ） |
| 通常投げの発生等 | データの `moves.throw`（発生5F・持続2F・空振り硬直20F が目安） |
| 成立条件 | 投げ判定ボックスが相手の「投げられる体」（pushboxを基準に縦に拡大、無敵状態でない）と重なる。相手が上記不可状態でないこと |
| 優先 | **同一フレームで打撃と投げが両方成立 → 打撃を優先**（投げ側の技は不発） |
| 投げ抜け | 投げが成立するフレームの**直前7F（`THROW_TECH`）以内に相手も投げ入力**していた場合、またはこちらが成立した瞬間に相手が投げ発生中の場合 → 双方が後ろへ弾かれ（各 ±40px / 12F の硬直）、ダメージなし。コマンド投げ（`throw.techable:false`）は抜けられない |
| 投げ後 | 投げ成立で被投げ側は `THROWN` 状態（`thrown`クリップ、`hold` に従い攻撃側の手元に固定）。`grabFrames` 後にダメージ+`launch`+ダウン。攻撃側は `attackerClip` の残りを行動不能で消化 |
| 技のあとの投げ無敵 | ガード/やられ硬直が終わった直後の3Fは**投げ無敵**（詰め寄り投げの連続を防ぐ） |
| 起き上がり直後 | 無敵終了後の最初の行動可能フレームから投げ可能 |

### 2.12 勝利ポイントと運勢（おみくじ）
勝利ポイント `winPoints`（0〜100）= `round(最終ラウンド終了時の勝者HP割合 x 60) + (ラウンドを1つも落としていない ? 25 : 0) + (ノーダメージで取ったラウンドがある ? 15 : 0)`。
`fortunes.ranks`（良い順）を上から見て `winPoints >= minPoints` を満たす最初の運勢を採用。最後の運勢は `minPoints:0`。
時間切れ勝ちは `winPoints` を 10 減らす（最低0）。

## 3. 入力システム

### 3.1 論理アクション

各プレイヤーは 9 個の論理ボタンを持つ: `up down left right`（方向）、`L`（弱）、`H`（強）、`S`（必殺）、`T`（投げ）、`start`。
メニュー操作もこの論理ボタンで行う（上下左右=移動、L=決定、H=戻る、S=補助、start=ポーズ/決定）。**キーボードだけは常に `Enter`=決定 / `Esc`=戻る / 矢印=移動も受け付ける**（パッドの設定が壊れていても必ず操作できる安全弁）。

### 3.2 デバイスとスロット

- デバイス種別: `KB1`（P1用配列）、`KB2`（P2用配列）、`KB3`（テンキー配列、任意の第3プリセット）、`PAD`（Gamepad APIの1台）。
- スロット（P1/P2）に1デバイスを割り当てる。キーボードとパッドは**混在可**（1P=KB1、2P=Joy-Con(R) など）。
- **自動割り当て（既定）**:
  - パッド0台: P1=KB1、P2=KB2
  - パッド1台: P1=KB1、P2=そのパッド
  - パッド2台以上: P1=1台目、P2=2台目（`index`の小さい順）
- 入力設定画面の「デバイス選択」で手動変更でき、手動設定は**自動より優先**して `localStorage` に保存（`slots`）。パッドは `プロファイルキー`（3.4）+ 接続順で識別。保存済みデバイスが存在しなければ自動割り当てにフォールバック。
- 同じデバイスを両スロットに割り当てられない（選択時に入れ替え）。

### 3.3 キーボードの既定配置

`KeyboardEvent.code`（物理キー位置）で判定する（JIS/US・IMEオン状態でも位置が変わらない）。入力欄が無いので全て `preventDefault`。**IMEがオンだと `keyCode 229` になる環境があるため、`code` を使い、BOOT画面に「IME は オフ にしてください」と小さく表示**。

| 論理 | KB1（P1） | KB2（P2） | KB3（テンキー、任意） |
|---|---|---|---|
| up | `KeyW` | `ArrowUp` | `Numpad8` |
| down | `KeyS` | `ArrowDown` | `Numpad5` |
| left | `KeyA` | `ArrowLeft` | `Numpad4` |
| right | `KeyD` | `ArrowRight` | `Numpad6` |
| L 弱 | `KeyF` | `KeyK` | `Numpad1` |
| H 強 | `KeyG` | `KeyL` | `Numpad2` |
| S 必殺 | `KeyH` | `Semicolon` | `Numpad3` |
| T 投げ | `KeyR` | `KeyO` | `Numpad0` |
| start | `KeyQ` | `KeyP` | `NumpadEnter` |

設計理由: P1を**左半分（WASD + FGH + R）**、P2を**右半分（矢印 + KL; + O）**に分け、同じ行列内（キーボードマトリクス）で同時押しが競合しにくいよう**左右で離した**。P1/P2のボタンキーは互いに隣接させない（`H`と`K`の間に`J`を空ける）。
- 追加: `Enter` / `Esc` は常にポーズ（どちらのプレイヤーとも無関係）。`Space` は未使用（ページスクロール抑止のため`preventDefault`のみ）。`F` ではなく `F11` は使わず、**フルスクリーンは `F2`**（`F`が戦闘ボタンのため）、ミュートは `F3`。
- ゴースト（同時押し取りこぼし）対策: 入力設定画面に**キーボードテスト**（押下中のキーが光る）を置き、「同時押しで反応しない組み合わせ」は設定画面で再割当てできる。ゴーストしやすい組合せの注意書き（「多くのキーボードは3〜4キー以上の同時押しが苦手です。パッド推奨」）を表示。
- 入力は `keydown` で**ラッチ**（そのフレームで押されて離されても1Fは押下扱い）し、ロジックステップが消費する。

### 3.4 Gamepad API の扱い

**ポーリング**
- `navigator.getGamepads()` を**rAFごとに1回**呼ぶ（毎回再取得。スナップショットを保持しない）。`gamepadconnected` / `gamepaddisconnected` は通知トーストと再評価のトリガーにのみ使う。
- 取得した状態は「最新サンプル」としてデバイスに保存し、各ロジックステップは**その時点の最新サンプル**を使う。サンプル間の短い押下は**ラッチ**（押下エッジをORして次ステップで消費）して取りこぼさない。
- `gamepad.connected === false` や `null` は未接続扱い。ブラウザがパッドを隠している間（何か押すまで）は未検出のままで、BOOT画面の「ボタンを押してください」で解決する。

**プロファイルキー（設定の単位）**
`gamepad.id` から `Vendor: xxxx Product: yyyy` を抽出して `"vid:pid"` を作る。無ければ `id` 全体を小文字化し80文字で切る。**Joy-Con(L) は `057e:2006`、(R) は `057e:2007` など別キーになる**ので、左右で別々のボタン設定とスティック設定が保存される。同機種2台は同じプロファイルを共有。

**入力の割り当て（バインド）の型**
- `{ "t":"b", "i": ボタン番号 }` … ボタン（ダイジタル/トリガー値>0.5でON）
- `{ "t":"a", "i": 軸番号, "s": +1|-1 }` … アナログ軸の片側（値 x s > しきい値でON。スティック用）
- `{ "t":"h", "i": 軸番号, "v": 値, "tol": 0.2 }` … ハットスイッチ軸（離散値。ブラウザによっては十字キーが軸になる。キャプチャ時の値vに ±tol で一致したらON）
- 1アクションに複数バインドを持てる（どれかがONならON）。

**既定値（Joy-Con 横持ち想定。実機で未検証の暫定値 — 展示前に必ずウィザードで確認）**

| 条件 | 既定 |
|---|---|
| `mapping === "standard"` の標準パッド | up/down/left/right = ボタン12/13/14/15 + 左スティック（軸0/1）、L=ボタン0、H=ボタン1、S=ボタン2、T=ボタン3、start=ボタン9 |
| `id` に `Joy-Con (L)` | 方向 = スティック（軸0/1）、スティック回転 **270°**、L/H/S/T = ボタン 0/1/2/3、start = ボタン8（−） |
| `id` に `Joy-Con (R)` | 方向 = スティック（軸0/1）、スティック回転 **90°**、L/H/S/T = ボタン 0/1/2/3、start = ボタン9（+） |
| 上記以外（非標準） | ボタン 0/1/2/3 を L/H/S/T、start=9、スティックは軸0/1 |

ブラウザ/OSで番号が変わるため、**既定は仮**。接続時に「未設定のコントローラー」と判断（保存済みプロファイルが無い）したら、トーストで「入力設定でボタンを割り当ててください」を促し、入力設定画面のウィザードへのショートカットを出す。

**スティック処理**
1. 軸値 `(x, y)` を読む（軸0,1。設定で変更可）。
2. **回転補正**: `rotation` = 0 / 90 / 180 / 270（度、画面上で時計回り、y下+座標）。`x' = x cosθ - y sinθ`、`y' = x sinθ + y cosθ`。横持ちJoy-Conで「物理的な向き」と「画面上の向き」を合わせるため。
3. **デッドゾーン**: 半径 `deadzone`（既定 **0.45**、設定0.2〜0.8）以内は無入力（Joy-Conのドリフト対策）。ヒステリシス: ONになるしきい値=deadzone、OFFになるしきい値=deadzone x 0.8。
4. **8方向化**: 大きさがONなら、角度で判定。`|x'|/大きさ > 0.38`（約22.5°）で左右、`|y'|/大きさ > 0.38` で上下。斜めも出る。
5. 方向ボタン（十字キーやボタンへのバインド）とORして最終の `up/down/left/right` にする。SOCD規則: **左右同時=ニュートラル、上下同時=上**。

**キャリブレーション（スティック向き自動検出）**
入力設定画面で「スティック向きを自動検出」: 「スティックを**右**に倒してください」（1.5秒保持）→ 平均ベクトルが (1, 0) に最も近くなる回転(0/90/180/270)を採用して保存。（右を倒すだけで十分: 回転のみ補正する想定のため）。

**接続/切断**
- 接続: 通知 + デバイス再評価（3.2）。保存済みプロファイルがあれば自動適用。
- 切断: 通知。非戦闘画面ならスロットを自動割り当てに戻す。戦闘中は自動ポーズ（1.5）。再接続は同プロファイルキー + 同スロットなら自動復帰。
- 複数のパッドが**同じidで入れ替わった**場合に備え、スロットには `プロファイルキー + 接続時のindex` を記録し、不一致なら画面で確認する。

**操作**
- 行を選んで決定 → 「**押してください…**（Esc: キャンセル / Del: 未割り当て / 5秒でタイムアウト）」の待機状態。対象デバイスの**次の入力**を捕捉して割り当てる。
  - ボタン: 押下エッジ。
  - アナログ軸: ベースライン（待機開始時の値）から |Δ|>0.5 かつ元の値が±0.15以内なら `{t:"a", i, s}`。
  - ハット軸（ベースラインが0近傍でない/離散値）: `{t:"h", i, v, tol:0.2}`。
  - キーボード: `event.code`。
- **待機開始から300msは入力を無視**（決定ボタン自身を拾わない）。待機中は他の全入力を無視。
- 重複: 同プロファイル内で既に別アクションに割り当て済みなら**入れ替え**してトースト「◯◯と入れ替えました」。
- **ウィザード**: 「↑ を押してください」→「↓」→「←」→「→」→「弱」→「強」→「必殺」→「投げ」→「スタート」と順に捕捉（Escで中断、Backspaceで1つ戻る）。完了後にスティック向き自動検出も実行。
- 設定は**変更のたびに自動保存**。「初期値に戻す」でそのプロファイルのみ既定へ。
- 画面内の操作は**キーボード（矢印/Enter/Esc）が常に有効**。パッドで操作する場合はスロットのデバイスの方向+L(決定)/H(戻る)。

**保存形式（localStorage、すべて try/catch、不可ならメモリ保持 + 「保存できません」を小さく表示）**
- キー接頭辞: `denno-hono:v1:`
  - `slots`: `{ p1: {kind:"auto"|"kb1"|"kb2"|"kb3"|"pad", key?:string, index?:int}, p2:{...} }`
  - `pads`: `{ "<profileKey>": { binds: { up:[B...], down:[...], left:[...], right:[...], L:[...], H:[...], S:[...], T:[...], start:[...] }, stick:{ enabled:true, rot:0|90|180|270, deadzone:0.45, axX:0, axY:1 } } }`
  - `kb`: `{ kb1:{...code}, kb2:{...}, kb3:{...} }`（既定との差分のみ）
  - `settings`: `{ volume, shake, glitch, scanline, rounds, time, easy:{p1,p2} }`
  - `last`: `{ p1:"miko", p2:"fox" }`（前回のキャラ）
- 不正データは破棄して既定へ。

### 3.6 入力フレームとバッファ

- 1ロジックステップごとに各プレイヤーの `InputFrame` を作る: 方向4bit(絶対) + ボタン4bit(`L H S T`) + start。
- 履歴は**リングバッファ 64F**。各フレームに「向き(facing)」と「相手との相対位置」を一緒に保存し、**前後入力（F/B）はそのフレームの向きで解釈**して数字方向（テンキー表記 1〜9、5=ニュートラル、6=前、4=後ろ、2=下、8=上）にする。
- ボタンのバッファ: 押下エッジを**6F**保持。実行された時に消費。自分のヒットストップ中はバッファが劣化しない。
- 方向の履歴は上書きせずに全フレーム残る。コマンド認識は履歴から行う。

### 3.7 コマンド認識（猶予フレーム）

**技の入力は固定**（data.js には書かない。技IDで決まる）:

| 技ID | 通常操作 | 簡易操作（3.8） |
|---|---|---|
| `5L` / `2L` / `jL` | 弱（立ち / ↓+弱 / 空中） | 同じ |
| `5H` / `2H` / `jH` | 強（立ち / ↓+強 / 空中） | 同じ |
| `throw` | 弱+強同時 または `T` | 同じ |
| `sp1` | **↓↘→ + 必殺**（236S） | 必殺 のみ（`S`単独） |
| `sp2` | **↓↙← + 必殺**（214S） | →+必殺（`6S`） |
| `super` | **↓→↓→ + 必殺**（236236S、ゲージ満タン） | ↓+必殺（`2S`、ゲージ満タン） |

**認識手順**
1. 必殺ボタン`S`の押下エッジが来たフレームから、過去 `CMD_WINDOW` フレームの方向履歴を取り出す。
2. 方向を**文字列化**: 各フレームのテンキー値（相対）を並べ、**連続する同値を1つに圧縮**。`8`（上）系は除去、`9`→`6`、`7`→`4` に正規化（ジャンプ入力でコマンドが壊れないように）。
3. 次の正規表現で判定（猶予を「斜め入力の省略」「斜めで終わる」まで許す）:

| コマンド | 正規表現（圧縮した文字列に対して部分一致） | 窓 |
|---|---|---|
| 236 | `2(3)?6` または 末尾が `23` | 16F |
| 214 | `2(1)?4` または 末尾が `21` | 16F |
| 236236 | `2(3)?6.*2(3)?6` | 36F |

4. 一致したらその技を**即時実行**。複数一致なら優先: `super` > `sp1/sp2`（236と214が両方一致したら、後半が新しい方）> 通常技。
5. ゲージが足りないとき `super` コマンドは**無視**して `sp1`（236）にフォールバック。
6. 通常操作で `S` を押したがどのコマンドにも一致しない場合は**何も起きない**（不発の小さなSE「ブッ」）。
7. 「弱+強」同時押し: `L` と `H` の押下エッジが3F以内に揃ったら投げ。ただし先に出た弱/強の技が**まだ発生前（startup中）**なら投げに**置き換え**る。すでに攻撃判定が出たら置き換えない。
8. 通常技の選択: 空中=`jL/jH`、↓を押している=`2L/2H`、それ以外=`5L/5H`（相手が近距離/遠距離で技を変える「近距離立ち」は無し。簡素化）。

### 3.8 簡易操作モード（初心者向け）

- プレイヤーごとにON/OFF（キャラ選択で`S`、または設定の既定）。**既定はON**（展示向け）。
- ON のとき、通常のコマンドも有効のまま、次の**追加マッピング**が効く（コマンドが一致しない場合のみ）:
  - `S`単独 または `4S/5S/7S`（前でも↓でもない） → `sp1`
  - `6S`（前+必殺） → `sp2`
  - `2S`（↓+必殺）または`1S/3S` かつゲージ満タン → `super`（ゲージ不足なら何もしない + 不発SE）
- 方向は`S`を押した瞬間（猶予2F）の入力で評価。地上のみ。空中の`S`は何も起きない。
- ON のプレイヤーには、HUDのゲージ脇に小さく「かんたん」バッジを出す。
- OFF のときは `S` 単独で何も起きない。通常のコマンドのみ。

### 3.9 アクションの優先順位（行動可能な状態のとき、毎ステップ）

1. （ヒットストップ中 → 処理せず、バッファだけ受ける）
2. `super`（コマンド or 簡易）
3. `throw`（`T` または 弱+強）
4. `sp1` / `sp2`
5. `5H/2H`（強）→ `5L/2L`（弱）。同時押しなら強優先
6. ジャンプ（↑）→ ダッシュ（ダブルタップ）→ しゃがみ（↓）→ 歩き（←→）→ 待機

攻撃中は、**キャンセル条件（4.12 `cancel`）を満たす技のみ**割り込み可能。

### 4.7 Boxes（ストッパー・やられ・押し合い。キャラクター空間）

  neon?:  { tubeW:3, glowW:8, glowAlpha:0.24, coreW:1, fill:0.9 },        // ネオン管描画の太さ(px)・グローのアルファ・暗い塗りの不透明度。省略時は左の値。すべて任意

#### 4.8.1 Feel（動きの気持ちよさの調整値。すべて任意）
```
feel: {
  breath:   { amp: 0.012, period: 90 },            // 待機中の手続き的呼吸（縦スケール±amp、周期F）。0で無効
  jump:     { sx: 0.94, sy: 1.08, frames: 4 },      // 離陸のストレッチ
  land:     { sx: 1.10, sy: 0.88, frames: 6 },      // 着地のつぶれ（outCubicで戻す）
  dash:     { sx: 1.06, sy: 0.97, frames: 5 },      // ダッシュ開始
  hitShake: { amp: [1, 2, 3, 3.5], },               // 被弾側のヒットストップ中の震え(px)。impact 1〜4 の順
  recoil:   { x: [3, 6, 10, 14], rot: [2, 4, 7, 10], frames: 4 },   // やられ反動（impact別の瞬間的な後退px・のけぞり度。描画のみ）
  squashHit:{ sx: 1.06, sy: 0.94, frames: 3 }       // 被弾時に衝撃方向へつぶれる
}
```
全て描画専用で、判定やロジックに影響しない。重いキャラは `land.sy` を小さく（0.84）、`recoil.x` を小さく、軽いキャラは `jump.sy` を大きく（1.12）。

### 4.9 リグとポーズ（重要: 角度の規約）

**全キャラ共通の骨格**（名前と階層は固定。長さと太さは `look.body` で変える）:

| ボーン | 親 | 始点 → 終点 |
|---|---|---|
| `pelvis` | (ルート) | 腰の位置（足元から計算） |
| `torso` | pelvis | 腰 → 首の付け根（長さ torsoLen） |
| `head` | torso | 首の付け根 → 頭の中心（長さ neckLen + headR） |
| `uarmF` `uarmB` | torso | 肩（胴の上端から shoulderDrop 下）→ 肘 |
| `farmF` `farmB` | uarm | 肘 → 手 |
| `thighF` `thighB` | pelvis | 腰 → 膝 |
| `shinF` `shinB` | thigh | 膝 → 足首 |
| `footF` `footB` | shin | 足首 → つま先 |

`F`=手前（描画が胴の前）、`B`=奥（描画が胴の後ろ）。ふつう F が相手側（前）の手足。

**Pose = 15チャンネルの数値（度、px）**

| チャンネル | 単位 | 意味（**すべて「前方向が+」**） |
|---|---|---|
| `rootX` | px | 体全体の前後ずらし（前+）。描画オフセット |
| `rootY` | px | 体全体の持ち上げ（上+）。`plant:"feet"`では全身が浮く（ホップ）、`"root"`では骨盤の高さ補正 |
| `rot` | deg | **体全体の回転**（骨盤を中心に前傾+ = 画面で時計回り）。ダウン/ふっとびで使用 |
| `torso` | deg | 胴の前傾（0=直立、+=前傾、−=後ろにのけぞる） |
| `head` | deg | 首の前傾（胴に対する相対。+=うつむく） |
| `uarmF` `uarmB` | deg | 上腕の振り（胴に対する相対）。0=だらんと下、**+90=真正面**、+180=真上、−90=後ろ |
| `farmF` `farmB` | deg | 肘の曲げ。0=まっすぐ、+=前腕が前方向（上腕から見て前上がり）へ曲がる（0〜150） |
| `thighF` `thighB` | deg | 太ももの振り（骨盤基準の絶対）。0=真下、+90=真正面（キック）、−=後ろ |
| `shinF` `shinB` | deg | 膝の曲げ。0=まっすぐ、+=膝が曲がる（すねが後ろへ。0〜150） |
| `footF` `footB` | deg | 足首。0=すねに直角（つま先は前）。+=つま先が上がる |

**FK（順運動学）の式（エンジン実装者向け、右向き・キャラ空間）**
- ボーンの「ワールド角 θ」: 0=真下、+90=前、180=真上、−90=後ろ。方向ベクトル = `(sin θ, -cos θ)`（キャラ空間 x前+, y上+。画面に出すときはy反転）。
  - `θ_torso = 180 - torso + (rot の影響は全体回転で別処理)`
  - `θ_head = θ_torso - head`
  - `θ_uarm = θ_torso + 180 + uarm`
  - `θ_farm = θ_uarm + farm`
  - `θ_thigh = thigh`
  - `θ_shin = θ_thigh - shin`（膝の曲げ。`shin`が+なら後ろへ）
  - `θ_foot = θ_shin + 90 + foot`
- 全体回転 `rot` は、組み上げた全点を**骨盤を中心に**画面で `rot` 度（時計回り+）回す。
- Decor/Chainのローカル座標 (x前+, y上+) → ボーンの現在姿勢での回転 `ρ = -(θ - θ0)`（時計回りdeg、`θ0`は中立: torso/head=180、arm/leg=0、foot=90）で回して、関節位置に足す。

**接地（plant）**
- `plant:"feet"`（既定）: **最も低い足裏**が足元(y=0)に来るよう骨盤の高さを自動計算し、さらに `rootY` を加算。立ち/しゃがみ/攻撃で膝を曲げると勝手に重心が下がる。
- `plant:"root"`: 骨盤の高さ = `restPelvisH + rootY`（+空中なら物理上の高さ）。ジャンプ・ダウン・投げられ状態など。
- `restPelvisH` は `basePose` を `plant:"feet"` で組んだときの骨盤の高さ（エンジンが起動時に計算。dataに書かない）。
- 足裏の最下点 = `足首から垂直方向の footH / 2`（足を水平とした場合）。
- 接地ポーズで前後の足の高さを揃えるコツ: 足の高さ ≈ `thighLen·cos(thigh) + shinLen·cos(thigh − shin)`。左右でこの値を±3px以内に。足裏を水平にするには `foot ≈ -(thigh - shin)`（すねの絶対角の符号反転）。

### 4.10 Clip（キーフレームアニメーション）

```
Clip = {
  length: int,               // フレーム数（1以上）
  loop?: bool,               // 既定 false
  plant?: "feet"|"root",     // 既定 "feet"
  blend?: int,               // このクリップへ切り替わるときの補間フレーム数。既定4（攻撃は1〜3、やられは1）
  base?: string,             // 省略時は basePose。別クリップ名を指定すると、そのクリップの f=0 のポーズを「欠けたチャンネルの基準」にする（しゃがみ技・空中技用）
  keys: Key[],               // fの昇順
  events?: [{ f:int, sfx:"step"|"land" }],   // 任意（歩きの足音など）
  squash?: [{ f:int, sx:number, sy:number, ease?:EaseName }]   // 任意。全身スケール(足元基準)のキー。省略は等倍(1,1)。打撃の瞬間のつぶれなどに（最初のf=0は(1,1)を暗黙とする）。描画専用
}
Key = { f: int, ease?: EaseName, back?: number, p: Pose部分 | "base" }
// back: ease が outBack / inBack / inOutBack のときのオーバーシュート量。既定1.70158、推奨0.8〜3.0（大きいほど行き過ぎる）
```

**補間の規則**
1. 各チャンネルは**独立したトラック**。そのチャンネルが `p` に書かれたキーだけが制御点。**f=0 で書かれていないチャンネルは、f=0 の値を `base`（なければ basePose）とみなす**。
2. キー間は**数値の線形補間にイージングを適用**。イージングは**到着側（後ろのキー）の `ease`** を使う（省略は `linear`）。例: `{f:11, ease:"outExpo", ...}` は直前のキーからこのキーへ「急加速して到着で減速」。
3. 最後のキーを過ぎたら**その値を保持**（`loop:false`）。`loop:true` はクリップ長で巻き戻る。最後のキー→（`length`で）f=0 への戻り区間は **f=0 のキーの `ease`** を使う。**ループクリップは f=0 のキーが必須**（`p:"base"` でも可）で、すべてのキーの f は `length` 未満。
4. `p:"base"` は**15チャンネルすべて基準姿勢の値**に戻すという意味（技の戻り用）。
5. 角度は常に**数値補間**（±180を跨ぐ最短回転はしない）。大きく回る動きは途中にキーを置く。
6. 時刻 t は技の開始フレームを 0 として進む（フレームn=1のとき t=0）。**攻撃判定が出る最初のフレームは t=startup**。打撃ポーズのキーは `f=startup`（そのフレーム）に置く。

**イージング名（固定）**: `linear` `inQuad` `outQuad` `inOutQuad` `inCubic` `outCubic` `inOutCubic` `outExpo` `inExpo` `inBack` `outBack` `inOutBack` `outElastic` `hold`（`hold`= 到着キーのfまで直前の値を保持して、f で一気に切り替わる）
- 使い分けの目安: 予備動作 `inOutQuad` / 打撃の瞬間 `outExpo`・`outCubic` / 引き戻し `inOutQuad` / ためて弾く `inBack` / 余韻 `outElastic`（弱めに）。

### 4.12 Move・Hit・Throw・Projectile

**技ID（固定10個）**: `"5L" "5H" "2L" "2H" "jL" "jH" "throw" "sp1" "sp2" "super"` — 全キャラ全て必須。入力は 3.7 で固定。

```
Move = {
  kind: "normal"|"special"|"super"|"throw",     // 5L..jH=normal / sp1,sp2=special / super=super / throw=throw
  name: string,                                  // 表示名（技表・超必殺カットイン）
  stance: "stand"|"crouch"|"air",                // 5L,5H,throw,sp*,super=stand / 2L,2H=crouch / jL,jH=air
  startup: int,  active: int,  recovery: int,    // フレーム。合計 total = startup+active+recovery
  clip?: string,                                  // 省略時は技ID。クリップの length は total と一致必須
  boxes: [{ f0:int, f1:int, x,y,w,h }],           // 攻撃判定。f0〜f1は技のフレーム番号(1始まり)で startup+1〜startup+active の範囲内
  hit: Hit | null,                                 // 打撃。投げ専用技/飛び道具専用技/移動技は null も可
  multi?: { count:int, every:int, final?:Hit },    // 多段。count回、every フレームごとに再ヒット。最後の1回だけ final を使う
  hurtOverride?: [{ f0:int, f1:int, boxes:[Box] }],   // 技中のやられ判定の上書き（例: 昇り技で上にのびる）
  invuln?: [{ f0:int, f1:int, type:"strike"|"throw"|"all" }],  // 無敵（技のフレーム番号）
  motion?: [{ f0:int, f1:int, vx:number, vy?:number }],        // f0〜f1の間 vx(px/F, 前+)をセット。vy は f0 に一度だけ与える初速(上+)
  spawn?: [{ at:int, projectile:string, x:number, y:number }], // 飛び道具を出す（atは技のフレーム番号。持続範囲内）。x,yは足元基準
  teleport?: { at:int, to:"behind"|"front", gap:number },     // 瞬間移動（相手の背後/正面 gap px）
  throw?: ThrowDef,                                // 投げ。kind:"throw" または コマンド投げ
  cancel?: { into:string[], frames:int },          // キャンセル。into は技ID。frames は接触(ヒット/ガード)後、ヒットストップ終了からの猶予
  cost?: int,          // super のみ。1000
  flash?: int,         // super のみ。暗転フレーム（既定40）
  landLag?: int,       // 空中中に始めた/空中に出る技の着地硬直
  trail?: { from:"handF"|"handB"|"footF"|"footB"|"prop", color:string, width:number, frames:int },  // 軌跡の見た目
  sfx?: string         // 開始時の効果音名（7章）
}
```

**空中判定のある技と物理**
- `motion.vy` を使う技はキャラが地面を離れる（重力は `stats.gravity` を毎F適用）。技のフレームが残っている間は着地しても技の残りを地上で消化（vx=0）。技のフレームが終わっても空中なら `jumpFall` に遷移して着地を待つ（行動不可）。着地で `landLag`（技になければ `stats.landLag`）。
- `stance:"air"` の技は着地した瞬間に技を終了し LANDING へ。

**Hit**
```
Hit = {
  damage: int,                 // 基礎ダメージ
  chip: int,                   // ガード時の削り（0可）
  level: "mid"|"low"|"high",
  hitstun: int,                // ヒット硬直(F)。effect:"launch" のときは 0 でよい
  blockstun: int,              // ガード硬直(F)
  hitstop: int,                // ヒットストップ(F) 0〜30
  knock: { hit:number, block:number },   // ノックバック総量(px)
  effect: "stun"|"launch",
  launch?: { vx:number, vy:number },     // effect:"launch" で必須。vx>0 = 攻撃側から遠ざかる、vy>0 = 上
  juggle?: int,                // launch時に付与する追撃回数。既定3。0=追撃不可
  gauge: { hit:int, block:int },  // 攻撃側のゲージ獲得(2.3)
  impact: 1|2|3|4              // 1=弱 2=中 3=強 4=超（火花の大きさ・SE・画面揺れ・グリッチの強さの基準）
}
```
- 空中ヒット: `effect:"stun"` が空中の相手に当たると 2.7 の既定の空中やられ。`launch` はそのまま適用。
- 多段 `multi`: ボックスは持続全体で有効。`every` フレームごとに「再ヒット可能」を立てる。最大 `count` 回。途中でガードされたら以降も当たる/ガードされる（各段で判定）。**コンボ補正は技ごとに1段扱い**。

**ThrowDef**（通常投げ `moves.throw` と、コマンド投げ（`sp1`等に `throw` を持たせた技）で共通）
```
ThrowDef = {
  box: { x,y,w,h },              // 成立判定（持続中に有効）。持続は move.startup+1〜+active
  techable: bool,                // 投げ抜けできるか（コマンド投げは false）
  damage: int,
  grabFrames: int,               // 掴んでから放すまで
  afterRecovery: int,            // 放した後に攻撃側が動けない時間
  attackerClip: string,          // 成立時に攻撃側が再生するクリップ。length = grabFrames + afterRecovery
  hold: [{ f:int, ease?:EaseName, x:number, y:number, rot:number }],   // 被投げ側の足元位置（攻撃側基準の前+/上+）と体の回転(deg)。f は 0〜grabFrames
  launch: { vx:number, vy:number },    // 放した時の吹っ飛び
  hitstop: int,                  // 放した瞬間のヒットストップ
  impact: 1|2|3|4,
  gauge: { hit:int }
}
```
- 成立しなかった場合は `move` の通常クリップ（`startup/active/recovery`）で空振りモーション。

**Projectile**
```
Projectile = {
  life: int,                     // 存続フレーム
  vx: number, vy: number,        // 初速(px/F)。vx は前+
  ax?: number, ay?: number,      // 加速度(px/F²)
  box: Box | null,               // 弾の中心を原点とした判定。null は見た目のみ
  hit: Hit | null,               // null は見た目のみ
  hits: int,                     // 何回ヒットで消えるか（1以上）
  hitEvery?: int,                // 多段のとき再ヒット間隔(F)。既定1
  maxActive: int,                // 同時に画面に出せる数（持ち主ごと）。1〜3
  priority: int,                 // 飛び道具同士の相殺。大きい方が残る。同値は両方消える。0は相殺しない
  ground?: bool,                 // true なら y を地面に貼り付け（衝撃波）
  follow?: bool,                 // true なら持ち主に追従（スポーン位置を維持）。ビームや演出に
  look: { style:"fuda"|"orb"|"shock"|"beam"|"ghost"|"slash", color:string(paletteキー), size:number, clip?:string }   // ghost は clip（持ち主のクリップ）を半透明で再生
}
```
- ヒットまたは `life` 満了で消滅。壁（ワールド端±60）を出たら消滅。ガードされても消える。

### 5.3 メインループ（固定ステップ + 補間描画）

1. rAFごとに `now`、`realDt = min((now - last)/1000, 0.1)`。
2. `DeviceManager.poll()`（パッドのサンプル取得、ラッチ更新）。
3. `acc += realDt * timeScale`。`steps = 0`。`while (acc >= STEP && steps < 5) { Scene.update(); acc -= STEP; steps++ }`。5ステップで打ち切ったら `acc = 0`。
4. `alpha = acc / STEP`。`Scene.render(ctx, alpha)`。
5. `FX.update(realDt)`（実時間）。
6. 描画は**常に**行う（ロジックが0ステップでも）。

**補間の対象（描画側）**: 位置(x,y)、向き、`ClipPlayer` のアニメ時刻、`rootX/rootY/rot`、Chainのノード位置、飛び道具位置、カメラ（中心/ズーム）。`prev` と `curr` を保持して `lerp(prev, curr, alpha)`。
**補間しない（スナップ）**: 向きの反転、瞬間移動、ラウンド開始位置、クリップ切替直後のブレンド（ブレンド自体は補間する）。これらは `snap` フラグを立てた1フレームだけ補間を切る。
**ヒットストップ中**: ロジックは止まるのでアニメ時刻も止まる。見た目の微振動だけ描画側で加える。

### 5.4 Fighter の状態機械

| 状態 | クリップ | 入る条件 | 出る条件 |
|---|---|---|---|
| `IDLE` | idle | 行動可能で入力なし | 入力で他状態 |
| `WALK_F` / `WALK_B` | walkF / walkB | ←→ | 入力変化 |
| `CROUCH` | crouch | ↓ | ↓を離す |
| `PREJUMP` | (idleのまま) | ↑ | prejumpフレーム後 `AIR` |
| `AIR` | jumpUp(上昇)→jumpFall(下降) | ジャンプ | 着地で `LANDING` |
| `LANDING` | landing | 着地 | landLag後 |
| `DASH_F` / `DASH_B` | dashF / dashB | ダブルタップ | 規定フレーム |
| `ATTACK` | 技ごと | 技入力 | 技終了 |
| `BLOCKSTUN` | guardStand / guardCrouch | ガード成立 | blockstun後 |
| `HITSTUN` | hurtHigh / hurtLow | ヒット（地上、stun） | hitstun後 |
| `AIR_HURT` | hurtAir | launch / 空中ヒット | 着地で `DOWN` |
| `DOWN` | down | 着地（launch後） | 28F or 受け身で `WAKEUP` |
| `WAKEUP` | wakeup | DOWN後 | 18F（全無敵） |
| `GRAB` | (attackerClip) | 投げ成立（攻撃側） | grabFrames+afterRecovery |
| `THROWN` | thrown | 投げ成立（被害側） | grabFrames後 `AIR_HURT` |
| `SUPERFLASH` | (待機) | 超必殺発動 | フラッシュ終了 → `ATTACK` |
| `INTRO` / `WIN` / `LOSE` | intro / win / lose | ラウンド進行 | Matchが管理 |

- **クリップ切替ルール**: 状態が変わるたびに `ClipPlayer.play(clipName, blend)` を呼ぶ。現在の**描画中ポーズ**を `snapshot` して、新クリップのポーズへ `blend` フレームかけて `inOutQuad` でブレンドする（ポップを防ぐ）。同じクリップへの再指定は無視（歩きの途切れ防止）。
- **アニメ時刻**: `ATTACK` は技のフレーム n に対して `t = n - 1`。他の状態はクリップ内で自走（loopは巻き戻し）。ヒットストップ中は進めない。
- **攻撃キャンセル**: 接触（ヒット/ガード）が成立した技で、ヒットストップ終了後 `cancel.frames` フレームの間、バッファされた入力が `cancel.into` に含まれる技なら割り込む。割り込み時は新クリップへブレンド1〜2F。

### 5.5 1ロジックステップの処理順（Fight）

1. 入力サンプル → 各 `InputBuffer` に `InputFrame` を push。
2. `Match` の進行（READY→FIGHTING など）、タイマー。
3. ヒットストップ残のあるFighterは `hitstop--` して以降のキャラ更新を**スキップ**（バッファは受ける）。それ以外のFighterは次へ。
4. 各Fighter: 状態更新（行動可能なら入力→行動決定、攻撃中なら `MoveRunner` を1F進める、`motion` で速度設定、`spawn`/`teleport` 実行、アニメ時刻更新）。
5. `Physics`: 重力・移動・ダッシュ・ノックバックの積分 → 押し合い → 壁/カメラ端クランプ（押し戻しの再配分）。
6. `Projectiles` の更新（移動・寿命・壁・相殺）。
7. `Combat`: 各攻撃ボックス（技と飛び道具）× 相手のやられボックス。**同フレームの全ヒットを集めてから**一括適用（相打ちあり。打撃と投げは打撃優先）。ガード判定 → ダメージ/ゲージ/硬直/ノックバック/ヒットストップ/FX/SFXの発行。
8. 向きの自動更新（地上で行動可能なら）。`SecondaryMotion`（Chain）を1ステップ。
9. `Camera` 目標更新と追従。KO/時間切れ判定。
10. `prev ← curr`（スナップショットをここで更新）。FXへイベントを渡す（実体は`FX.update`で進行）。

### 5.6 Renderer の描画順

1. ステージ背景（キャッシュ済みレイヤーを視差付きで）
2. 影（足元の楕円。高さで縮む・薄くなる）
3. 奥のキャラ → 手前のキャラ（**直近に攻撃を出した側を前**。各キャラは `fighterLayer`（オフスクリーン）に描いて、フラッシュ/グリッチ/浄化の加工後に本画面へ）
4. 飛び道具、軌跡、残像（加算合成）
5. FX（火花、リング、パーティクル、グロー、浮遊ダメージ）
6. 前景（灯籠のボケ、花びら/データ片）
7. HUD（カメラ変換なし）
8. バナー、フラッシュ、走査線 + ヴィネット、グリッチの全画面パス

### 5.7 スケーリング・キャンバス
- 論理960x540を保ち、`s = min(innerWidth/960, innerHeight/540)` で拡大・中央配置（余白は `#05060f`）。バッキングストアは `devicePixelRatio` を考慮（`min(dpr, 2)`）。`resize` はデバウンス100ms。
- `getContext('2d', { alpha:false })`。`image-rendering` は既定のスムージングを使用。
- `cursor:none`、`user-select:none`、`contextmenu` 抑止。フルスクリーン `F2`、ミュート `F3`。

### 5.8 ハッシュパラメータ（クエリ文字列は使わない）

| ハッシュ | 動作 |

### 5.9 プール容量・性能目標
飛び道具16 / パーティクル800 / 浮遊テキスト24 / 残像12。`shadowBlur` は**毎フレーム使用禁止**（グローは事前描画スプライトの`lighter`加算、またはネオン管の多重ストローク。6.2）。目標: 60fps（一般的なノートPC）、144Hzでも滑らか。1キャラの描画はパス約100未満。

### 5.10 `#selftest`（ヘッドレス高速自動対戦）— 必須

**目的**: テスト環境では `requestAnimationFrame` が止まる/極端に遅いことがあるため、**描画ループにもデバイス入力にも依存せず**、60Hz固定ステップのロジックだけを CPU 同士で回して不具合を検出し、結果を画面に出す。

**起動**: `#selftest`（任意キー: `matches=N` 既定12、`seed=N` 既定1、`maxSec=N` 既定20＝全体の時間上限、`chars=miko,fox` 既定は roster 全組み合わせ）。

**駆動方法**
- `Scene` を経由せず `Match` + `Fighter` + `Combat` + `Physics` + `Projectiles` を直接生成して `step()` を呼ぶ。**`Audio` と `Renderer` は呼ばない**（`FX` はイベントを捨てる null 実装を渡す）。
- ループは `setTimeout(0)` / `MessageChannel` で**時間予算（1チャンク 12ms）**ごとに分割して回し、チャンクの合間に結果パネルを更新する（UIが固まらず、rAFにも依存しない）。1チャンクで回せるだけ `step()` を回す（実時間とは無関係の最高速）。
- 乱数は seed 固定（ロジック用）。同じ seed・同じ組み合わせは**同じ結果**になること（決定論）。
- **試合の組み合わせ**: roster の全ペア（鏡対戦含む）を順に、`matches` 件に達するまで。各試合は通常ルール（2本先取、時間99秒）で、KO/TIME_UP/ドローを含め `MATCH_END` まで。

**CpuPolicy（簡易AI。テスト用であり強さは不要）**: 毎フレーム `InputFrame` を生成。
- 距離で行動を重み付き抽選（遠: 歩き前/ダッシュ/`sp1`/ジャンプ、中: 歩き/`5L`/`5H`/`2L`/`2H`、近: `5L`連打→キャンセル/投げ/ガード）。1つの行動を 6〜24F 続けてから再抽選。
- ガード（相手の攻撃発生を見たら後ろ入力 + しゃがみ）を 35% の確率で選ぶ。ゲージ満タンなら `super` コマンドを 30% で入力（コマンドを**実際の方向列で入力して** `CommandParser` も通す）。簡易操作は試合ごとに ON/OFF 交互。
- **全技を踏むためのカバレッジ誘導**: 各キャラで未使用の技IDがあれば、その技を出す確率を上げる。

**検出する項目（assertion）** — 毎ステップ（または1Fおきに）チェックし、違反は `failures` 配列に `{match, frame, check, detail}` で記録（同じ種類は最大5件ずつ）。
1. **例外**: `step()` 全体を try/catch。スタックを記録して**その試合は中断し次の試合へ**。
2. **数値の健全性**: x,y,vx,vy,HP,ゲージ,ポーズ値が `NaN`/`Infinity` でない。HPは 0〜max、ゲージは 0〜1000。
3. **位置**: キャラxが [40,1240] 内、2人の距離 ≤ 880+誤差、地上キャラの y=0、押し合いで重なったまま 30F 続かない。
4. **状態機械**: 未知の状態名にならない。同一状態に 600F 以上居続けない（`IDLE` を除く。ハング検出）。技のフレームカウンタが total を超えない。クリップ名が存在する。
5. **ラウンド進行**: 1ラウンドが 5400F（制限時間99秒+余裕）以内に決着する。`MATCH_END` に到達する。ハング（500F 全く状態が変わらない）を検出。
6. **ルール**: 削りでHPが0にならない。コンボ補正が 0.3〜1.0。ヒットストップが 0〜30。
7. **カバレッジ**: 各キャラについて、全10技を「出した」「ヒットした/ガードされた」回数。出していない技は `warning`。
8. **アニメ**: 各フレームでポーズをサンプルして全チャンネルが有限、FK計算が有限、`plant:"feet"` で最下点の足が地面±1px（床抜け/浮き検出）。
9. **決定論**: 最初の1試合を同じ seed でもう一度回し、**最終状態のハッシュ（HP・位置・フレーム数）が一致**すること。
10. **データ検証**: `validateGameData` の errors/warnings 件数を表示。

**画面表示**（等幅フォント、論理960x540、スクロール不要）
```
SELFTEST  seed=1  matches=12   [RUNNING 7/12]  PASS|FAIL
elapsed 3.2s   steps 412,800   speed 129,000 steps/s (= 2150x realtime)
rounds: 41  KO 29 / TIMEUP 9 / DRAW 3   avg round 1420F (23.7s)   max 3210F
errors: 0   failures: 0   warnings: 2   data: errors 0 / warnings 1
per-char coverage:  miko 10/10  komainu 10/10  oni404 9/10 (sp2 未使用) ...
per-pair win:  miko-komainu 2-1 ...
determinism: OK (hash 9f3a21c0)
failures:  (最新5件) [m3 f812 NaN] fighter.x ...
```
- 終了時に **`document.title` を `SELFTEST PASS ...` または `SELFTEST FAIL ...`** に更新し、`window.__selftest = { pass, failures, warnings, stats, coverage, ... }`（JSONシリアライズ可能）を公開する。テスト側がスクリーンショットでもJS評価でも判定できるように。
- 総実行時間が `maxSec` を超えたら打ち切り、`INCOMPLETE` と表示（`pass` は false）。
- **合格条件**: failures 0、全試合が `MATCH_END` に到達、決定論 OK、`data errors 0`。

**補足（rAF が止まる環境への保険）**: 通常モードでも、起動後 500ms 以内に rAF コールバックが一度も来なければ、`setTimeout(16)` 駆動に切り替えて動かす（同じ `frame(now)` を呼ぶ）。`#debug` に「driver: rAF|timer」を表示。

### 5.11 `#gallery`（ポーズ一覧）— 必須

**目的**: スクリーンショット1枚で全キャラの全技の絵の崩れ（関節の逆折れ、足の浮き、ポーズの破綻、パーツのズレ）を確認する。描画は**静止画**で、ロジックも rAF も不要（ハッシュ変更・キー操作時に1回描画。`setTimeout` でも描ける）。

| ハッシュ | 内容 |

| `#gallery` | roster 先頭キャラの**全クリップを1ポーズずつ**（下記）を並べたページ。キャラ名とクリップ名を各セルにラベル |

| `#gallery&c=miko&move=5H` | 1つの技を**時系列で並べる**（f=0, 発生直前（溜めの頂点）, f=startup（打撃）, 持続末, 硬直中央, 最終F の6枚を大きく）+ 判定ボックス重ね |

全体が「暗いネオン」単一テーマ。`:root { color-scheme: dark }`。

### 6.2 キャラクターの画風と「動きの気持ちよさ」

**画風の大方針**: 細かい顔・服の描き込みはしない。**「ネオン管のように光るシルエット + 幾何学的なパーツ」**で見せ、情報量は**動き**に回す。キャラの差は **色・体型・シルエットの特徴**（巫女=長い袖と髪、狐=大きな尻尾、404鬼=角と巨体、狛犬AI=四つ足寄りの前傾姿勢）でつける。顔は**目の光（1〜2本の線か点）だけ**（`decor` の `line`/`circle` + `glow`）。口・鼻・髪の毛筋・服の柄は描かない。

**ネオン管レンダリング（全パーツ共通の描き方）**
1. 各パーツ（胴・手足・頭・decor・chain）は **暗い塗り**（`outline` 色に近い暗色。`look.neon.fill` で不透明度0.85〜1）で面を作り、
2. その輪郭を**ネオン管**として3層で描く: ①**グロー層**（`glow`/パーツ色、太さ `neon.glowW` 6〜10px、アルファ `neon.glowAlpha` 0.18〜0.3、加算合成）→ ②**管の本体**（パーツ色、`neon.tubeW` 2.5〜3.5px）→ ③**芯**（白に近い `#f4f7ff`、`neon.coreW` 1px、アルファ0.9）。
3. **`shadowBlur` は毎フレーム使わない**。グロー層は「同じ輪郭を太く淡くもう一度ストロークする」+ `globalCompositeOperation='lighter'`、または**パーツ種別ごとの事前描画スプライト**（円・カプセルの形を `SpriteCache` に焼いておき、位置/回転/スケールで `drawImage`）で出す。キャラ全体のグローは `fighterLayer` を縮小して加算で重ねるだけの軽い方法（低解像度ぼかし）も可。
4. 面の塗りは `colors` のパレット色を**暗く落とした**値（エンジンが `color x 0.28`）で塗り、管の色にパレットの明るい色を使う。キャラごとの色味は**管の色**で出る。
5. 発光するのは「輪郭・目・回路ライン・小物の先端」だけ。面積の広い部分は暗くして、シルエットが一目で分かるようにする。

**構造**
- 胴は**テーパー付きの多角形**（肩幅 `torsoWTop` → 腰幅 `torsoWBottom`）。腰の**ヒップブロック**（丸み矩形）で胴と太ももを繋ぐ。
- 手足は**テーパー付きカプセル**（`limbW`）。関節に小さな円（管の節）で継ぎ目を見せる。手は円（`handR`）、足は丸矩形（`footLen` x `footH`）。
- 頭は円または幾何形。耳・角・鬣・面などは `decor`（`tri` `poly` `circle` `line`）で足す。**四つ足寄り（komainu）は胴を前傾 + 腕を長く太くし、`basePose.torso` を 35〜45 付近に、前腕を床近くまで下ろす構え**にしてシルエットで区別する。
- リムライトは不要（ネオン管の芯が同じ役割）。

**ぬるぬるを生む仕組み（全部入れる）**
1. 60Hzロジック + **alpha補間**で高リフレッシュでも滑らか。
2. ポーズは**キーフレーム + イージング**（予備動作→打撃は`outExpo`で急加速→減衰して引き戻し）。1フレーム目の「溜め」を必ず作る。
3. **クリップ間ブレンド**（`blend`フレーム）でポップを消す。
4. **二次揺れ**: 髪・袖・尻尾・帯・リボンが慣性で遅れてついてくる（`Chain`）。ヒット時はインパルス（受けた方向に±）を加えて跳ねさせる。
5. **スカッシュ&ストレッチ**（描画のみ）: ジャンプ離陸で縦1.08/横0.94（4F）、着地で縦0.88/横1.10（6F、イーズ戻し）、ダッシュ開始で進行方向に1.06。足元基準でスケール。
6. **残像**: ダッシュ・突進・超必殺中、3フレームごとの過去ポーズを4枚、アルファ0.28→0.05、加算合成（`glow`色で着色）。
7. **軌跡**: 技の`trail`（手/足/小道具の先端の過去位置8個を帯状に結ぶ、先端が太く`glow`色、加算）。持続フレーム中のみ。
8. **着地・ダッシュの砂煙**（データ片の粒）。足音 `step` イベントで小粒を出す。
9. ヒットストップ中の被弾側 ±(1〜3)px 振動（交互にXを振る）。
10. アニメの「高速部」で先端が長く伸びる**スミア**（任意P2）: 先端速度がしきい値超なら先端カプセルを後ろに2枚薄く描く。

### 6.2.1 動きの気持ちよさを作る仕組み（スキーマ + エンジン）

動きで見せることが最優先。次の仕組みを**データで調整できる形**で持つ（詳細フィールドは 4.8〜4.10）。

| 要素 | 仕組み | 調整場所 |
|---|---|---|
| **予備動作（溜め）** | 発生前の数フレームで逆方向へ引くキー（`inOutQuad`）。技の重さで溜めの長さを変える（6.2.2） | Clip の keys |
| **打撃のスナップ** | 打撃キーを `outExpo`（急加速して到着）か `outBack`（行き過ぎて戻る）にし、**到着を `f=startup` に置く**（判定が出るフレーム）。その直前フレームとの差を大きくして「パチン」と見せる | Clip の keys、`Key.back`（オーバーシュート量） |
| **オーバーシュート** | `outBack` + `back` 係数（既定1.70、0.8〜3.0。小さいほど控えめ）。または打撃キーの直後に「行き過ぎキー」を置き、少し戻す（フォロースルー） | `Key.back` / keys |
| **フォロースルー** | 持続中も `linear` でわずかに伸ばし続け（腕+4〜6°、胴+2〜4°）、硬直の前半は止めて**保持**、後半で `inOutQuad` で戻す | keys |
| **スカッシュ&ストレッチ** | 全身スケール（足元基準）。**クリップごとの `squash` トラック**で技中に指定でき、離陸/着地/ダッシュ/被弾は `look.feel` の自動値で付く | `Clip.squash`、`Character.feel` |
| **着地のつぶれ** | 着地で縦 0.88 / 横 1.10 → 6Fで 1.0 へ `outCubic`。砂煙 | `feel.land` |
| **ヒットストップ中の震え** | 被弾側が ±amp px で交互に震える（ヒットストップ残に比例して減衰）。攻撃側は逆に 0.5px のみ | `feel.hitShake`（impact別amp） |
| **やられ反動（のけぞり）** | 被弾の瞬間に `hurt*` クリップの先頭キーを**強めのポーズ**にし（`outExpo`）、さらに `feel.recoil` で体全体を ±px/度 だけ**逆方向に瞬間的に弾いてから戻す**（描画のみ、2〜4F） | hurt クリップ、`feel.recoil` |
| **揺れ物の遅れ追従** | `Chain` のバネ・減衰・慣性。本体の加速度に対する遅れ（`inertia`）と、被弾時の跳ね（`kick`） | `Chain.stiffness/damping/gravity/inertia/kick` |
| **待機中の呼吸** | `idle` のキー（膝・肩・腕の往復）+ 手続き的な呼吸（胴のスケール縦±1.2%、`feel.breath`）。揺れ物にも微小な風を足す | idle、`feel.breath` |
| **ブレンド** | クリップ切替時に `blend` フレームで現在ポーズからなめらかに | Clip.blend |
| **カメラ** | 強攻撃のヒットでズームパンチ、画面揺れ（6.6） | 6.6 |

**イージング（固定名）**: `linear` `inQuad` `outQuad` `inOutQuad` `inCubic` `outCubic` `inOutCubic` `outExpo` `inExpo` `outBack` `inBack` `inOutBack` `outElastic` `hold` — 太字の使い分け: 予備動作 `inOutQuad`、打撃 `outExpo`（鋭い）/ `outBack`（弾む）、フォロースルー `linear`、戻り `inOutQuad`、かたく止める `hold`。

**スカッシュ&ストレッチの自動値（`feel` 既定。キャラごとに上書き可）**
- 離陸: 縦 1.08 / 横 0.94（4F、`outQuad`で戻す）。着地: 縦 0.88 / 横 1.10（6F、`outCubic`で戻す）。
- ダッシュ開始: 進行方向 x1.06 / 縦 0.97（5F）。重い技の打撃: 縦 0.96 / 横 1.04 を打撃フレームに1〜2F当てて戻す（`squash` トラックで技ごとに指定）。
- ヒット被弾: 衝撃方向に縦横を 0.94/1.06 で 3F。
- スケールは足元（キャラ空間の原点）基準。当たり判定には影響しない。

**Chain のバネ減衰パラメータの意味**（4.8の表と対応）
- `stiffness`（休止方向へ戻る力）が大きい→硬い（髪の束先）、小さい→ふわふわ（袖・尻尾）。
- `damping` が小さい→ゆらゆら長く揺れる、大きい→すぐ止まる。**尻尾は 0.08〜0.12、髪は 0.12〜0.16、袖は 0.14〜0.2**。
- `inertia`（本体の加速度の効き、既定1.0）: 大きいほどダッシュや技の開始で大きく後ろに流れる。重い大物（鬣・尻尾）は 1.3〜1.6。
- `kick`（ヒット/着地での跳ね返りの倍率、既定1.0）。
- `gravity` は垂れ下がり。尻尾や髪は 0.2〜0.4、重い袖・腰布は 0.5〜0.7。
- 安定性: 1ステップの移動量を `segLen` の半分以内にクランプ（暴れ防止）。ヒットストップ中は更新しない（見た目は止まる）が、ヒット瞬間に `kick` を一度加える。

### 6.2.2 技のキーフレームの作り方の指針（Haiku向け）

> 目的: 誰が作っても「溜め→パチン→余韻→戻り」の気持ちいい動きになるようにする。**キーフレーム数は 1技あたり 4〜6個**。キーの `f` は技の `startup`/`active`/`recovery` から次の表で**機械的に決める**。

**基本の型（4〜5キー）**。S=startup、A=active、R=recovery、total=S+A+R。

| 区間 | キーの置き方 | ease | 内容 |
|---|---|---|---|
| ①溜め（予備動作） | `f = S - W` （W=溜めの長さ）に溜めの頂点 | `inOutQuad` | 打撃と逆方向へ引く（腕を後ろへ、胴をのけぞる、重心を後ろ足へ）。**ここに `rootX` を −2〜−8** |
| ②打撃（スナップ） | **`f = S`**（攻撃判定が出る最初のフレーム） | `outExpo`（弱・中）/ `outBack`（強・必殺） | 前へ振り切る。胴を前傾 +10〜30、`rootX` を +6〜+14（踏み込み）、前足を出す。**溜めの頂点から打撃までは最短 `snap` フレーム** |
| ③フォロースルー | `f = S + A - 1`（持続の最後） | `linear` | 打撃ポーズからさらに +4〜6°伸ばす、`rootX` をさらに +2〜3 |
| ④止め（硬直の頭で保持） | `f = S + A + round(R x 0.25)` | `hold` または `linear` で値をほぼ維持 | 振り切ったまま止まる（隙を見せる）。弱技はこのキーを省略可 |
| ⑤戻り | `f = total - 1`（最後のフレーム） | `inOutQuad` | `p:"base"`（構えに戻る） |

**技の種類ごとの数値（W と snap と戻り）**

| 技の種類 | 溜め W（打撃の何F前に頂点） | 溜めの量 | 溜め頂点→打撃の `snap` | 打撃の ease | フォロースルー | 戻りに使うR |
|---|---|---|---|---|---|---|
| 弱（立ち/しゃがみ） | 3F（S=4〜5なら f=2） | 小（腕 −15〜−30°、`rootX` −2〜−3） | **2〜3F** | `outExpo` | 持続末に +4° | 後半 60% で戻す |
| 強（立ち/しゃがみ） | **6〜8F**（S=11〜15なら f=4〜8） | 大（腕 −40〜−80°、胴 −8〜−14°、`rootX` −6〜−8、**頂点で1〜2F静止**） | **2〜3F**（溜めてから一気に） | `outExpo`（斬撃）/ `outBack`（叩きつけ） | +6° + 保持 | 後半 50% で戻す、前傾のまま長く止める |
| ジャンプ攻撃 | 2〜3F | 小〜中 | 2F | `outExpo` | +4° | 着地まで構えを崩さない |
| 飛び道具の発射 | 6〜8F | 中（手を引く/頭上に構える） | 3〜4F | `outExpo`（放つ瞬間）、直後に反動で手を少し戻す（`outBack`） | 腕を伸ばしたまま保持 | R の 70% は保持 |
| 昇り/対空 | 3F（しゃがんで溜める） | 大（膝を曲げる） | **2〜3F** | `outExpo`（跳ね上がる） | 頂点で伸びきって保持 | 下降中は `inOutQuad` で戻す |
| 突進 | 6〜8F（身を低くして後ろへ） | 大（胴を前傾、`rootX` を後ろに） | 2F | `outCubic` | 突進中は姿勢を保つ | 急停止を `outBack` |
| 投げ（空振り） | 3F | 中（両腕を前に開く） | 2〜3F | `outCubic` | 掴んだまま保持 | 後半で戻す |
| 超必殺 | 6F（大きく構える。暗転後） | 最大（体全体で引く） | **3F** | `outExpo` + 直後に `outBack` 追加 | 長い保持 | 後半 40% でゆっくり戻す |

**作り方の手順（コピペ可能）**
1. 技の S,A,R を決める → total を計算 → クリップの `length` = total。
2. 溜めキーを `f = S - W`（弱は `f = max(2, S-3)`）に置く。`ease:"inOutQuad"`。
3. 打撃キーを **`f = S`** に置く。弱=`outExpo`、強・必殺=`outBack` と `back: 1.2`（好みで 0.8〜2.0）。
4. 持続の最後（`S + A - 1`）に `linear` でフォロースルーのキー。
5. 硬直の頭 25% 地点に保持キー（強・必殺・足払いのみ）。
6. 最後は `f = total - 1` で `p:"base"`（`inOutQuad`）。
7. `trail` を付ける（打撃フレーム〜持続末）。重い技は `squash` で打撃の1F だけ縦0.96/横1.04 を入れる。

**ポーズの勘所**
- 打撃のポーズは**腕を一直線に伸ばす**（`uarmF≈85〜95` かつ `farmF≈0〜8`）。蹴りは `thighF≈70〜95`、`shinF≈0〜10`、軸足は膝を曲げる（`thighB≈−10`、`shinB≈25`）。
- 重い技ほど**体全体（torso、rootX、rot±2〜6°）**を動かす。腕だけで終わらせない。
- 戻りは打撃より**ゆっくり**（ease は `inOutQuad`、区間が長いほど重く見える）。
- **やられ**: 先頭キーは `f=1〜2`、`outExpo`、`torso −16〜−34`、`head −22`、腕を跳ね上げる。`f=10〜12` で少し戻す（余韻）。上段は胴をのけぞらせ、下段は前かがみにする。
- **待機の呼吸**: 36〜45Fで往復。膝（thigh/shin ±3〜4°）+ 肩/腕（±4°）+ 胴（±2°）。`inOutQuad` で。キャラごとに周期を変える（oni404 は 90F でゆっくり、fox は 54F で速く）。
- **ダッシュ/ジャンプ**: 離陸は直前に膝を曲げる（`prejump` 中は `jumpUp` の f=0 手前で屈伸を `squash` で補う）、空中の頂点で手足を少し開く。

## 7. 効果音（Web Audio合成）

### 7.1 基盤
- 初回の入力で `AudioContext` を作成して `resume`。`DynamicsCompressor` → `masterGain`（設定の音量 x 0.35）。
- ヘルパ `tone({type, f0, f1, dur, gain, attack, filter})`（周波数スイープ + エンベロープ）、`noise({dur, gain, filterType, fq0, fq1})`（フィルター付きノイズ）。
- SFXごとの**最小間隔**と**同時発音上限20**。ステレオパン（P1=−0.3 / P2=+0.3、画面位置に追従）。
- BGMは**P2（任意）**: 4小節の低音ドローン + 軽い和風スケール（五音音階）のアルペジオをロード不要で生成、音量は戦闘中0.15。

## 9. バランス指針と残り3キャラの仕様

### 9.1 共通の方針
- 1ラウンドの平均は **40〜60秒**、1キャラのHP 1000 を **3〜4回の接触**（約25〜30%ずつ）で削る想定。1コンボは通常20〜30%、最大でも40%。
- 勝ちパターンは「差し合い → 小技から強で刻む → 必殺でキャンセル → ゲージで大祓」。**どのキャラにも明確な長所と弱点**を持たせる。
- 数値の目安: 超必殺は素点 約300（コンボ補正0.4以上で最低120）。投げは素点 100〜160。

### 9.2 フレーム有利の目安（`hitstun/blockstun` の決め方）
有利フレーム = `hitstun − 残り`（接触が持続1F目としたとき `残り = (active−1)+recovery`）。**逆算して決める**: `hitstun = 残り + 狙いの有利F`。

| 技 | ヒット有利 | ガード有利 | 例（miko 5L: 残り10） |
|---|---|---|---|
| 弱（立ち/しゃがみ） | +4〜+6 | 0〜+2 | hitstun 15 / blockstun 11 |
| 強（立ち） | +2〜+4 | −4〜−2 | 5H: 残り20 → hitstun 24 / blockstun 16 |
| 足払い（下段強） | ダウン | −10〜−14 | 2H: 残り24 → blockstun 12 |
| 必殺（技中） | 技ごと | −8〜−3 | - |
| 昇り技（対空） | ダウン | −18〜−28 | sp2 |
| 超必殺 | ダウン | −20以下 | - |
| 飛び道具 | +2〜+6（遠距離） | 0〜+4 | fuda |

### 9.5 Haiku向け作業手順
1. 8章の `miko` をコピーして `komainu / oni404 / fox` を作る。**IDキーと `id`/`name`/`nameEn`/`title`/`blurb`/`ratings`/`quotes` を書き換える**。
2. `stats` と `boxes.push` は 9.3 の表から。`boxes.hurt` は見た目の高さに比例して拡大/縮小（oni404は 約1.15倍、foxは 約0.95倍）。
3. **基本動作のクリップ（20個）は miko のものを複製**し、次の差分だけ上書きする。
   - komainu: `idle`/`crouch` の `torso` +4（前傾で重心が低い）、`thigh` を +4 広め
   - oni404: `idle` の `torso` を 2 に、`uarm` を +10（腕が太く広い）、`walk` のキー間隔を x1.3（遅い）。`length` もそれに合わせる
   - fox: `idle` の呼吸を速く（length 54）、`walk` を x0.85（速い）、`crouch` を低く（`thighF` 80）
4. 攻撃クリップは miko を雛形に、打撃ポーズを変える（komainu=頭突き・拳、oni404=金棒の振り下ろし（`prop:"kanabo"`）、fox=蹴り・尻尾）。**キーの `f` は `startup`（打撃のf）に置く**。フレーム数は 9.3 の表に必ず合わせる。**クリップの `length` = 発生+持続+硬直**。
5. `look` は 6.4 の表の色と特徴で。`decor` 5〜8個、`chains` 2〜5個。`paletteP2` は必ず作る。
6. **攻撃クリップのキーは 6.2.2 の表で機械的に決める**（溜めの頂点 `f=S-W`、打撃 `f=S`、フォロースルー `f=S+A-1`、保持、戻り `f=total-1`）。komainu は `basePose.torso` を 38 前後の前傾にし、`idle`/`walk`/`guard` もそれに合わせた前傾ポーズにする。
